## Требование (словами владельца)

> У меня есть несколько начатых книг, часть из них — учебники. Я хочу фиксировать своё продвижение по книгам, внося информацию, сколько страниц, к примеру, я прочитал сегодня. Потом мы расширим отображение reading-а, чтобы панель книги, у которой есть соответствующая информация, могла развернуться, и там была бы полоска прогресса, на которой было бы видно моё продвижение (возможно, разные дни — разные цвета).

Дополнение от 2026-11-01:

> При отображении будем создавать несколько полос прогресса, если я, например, отложу книгу, дочитав до 100 страницы, потом забуду всё и вернусь перечитывать с 50-й. Тогда у нас появится ниже новая полоса, а старая никогда не заполнится.

## Сводная спецификация

Выведена из таблицы решений ниже. При расхождении права таблица.

### Данные

- `readings.total_pages` — integer, может быть пустым.
- `readings.attempt` — integer, not null, по умолчанию 1. Номер текущего захода; только растёт и хранит, сколько попыток было предпринято.
- Таблица `reading_progresses`, модель `ReadingProgress`:
  - `reading_id` — FK, not null, индекс;
  - `date` — date, not null, в форме по умолчанию сегодня;
  - `from_page`, `to_page` — integer, not null; это **позиции-закладки**: страница — точка на отрезке, а не объём;
  - `attempt` — integer, not null; номер захода, к которому относится запись;
  - `note` — text, может быть пустым: «Глава 4», «Главы 4 и 5», «рассказывается о нюансах владения в Rust»;
  - timestamps.
- Связи: `ReadingProgress belongs_to :reading, touch: true`; `Reading has_many` записей прогресса.
- Валидации: `0 ≤ from_page < to_page`. Верхняя граница (`to_page ≤ total_pages`) не проверяется. Привязки к `start` и `finish` reading-а нет.

### Создание записи

Бизнес-логика — по образцу `app/mutations/` (например, `ReadingProgressCreation`), всё в одной транзакции:

1. Если отмечено «Начать заново», `reading.attempt` увеличивается на 1.
2. Запись получает `attempt = reading.attempt`.
3. Если у reading-а есть записи с той же датой и тем же `attempt`, которые стыкуются с новой вплотную (`to_page` одной равно `from_page` другой, с любой стороны), они сливаются с новой в одну запись. Остаётся самая ранняя по `created_at` запись.
4. Заметки при слиянии склеиваются в порядке ввода. Каждая непустая часть помечается временем, когда её ввели (`created_at` записи-источника, для новой записи — текущее время, часовой пояс приложения), части разделяются пустой строкой:

   ```
   14:11 Глава 4

   16:20 Глава 5
   ```

   - Помечаются все непустые части, даже если непустая всего одна. Тогда непомеченная заметка всегда значит «запись ни разу не сливалась, заметка введена при создании», и её время можно брать из `created_at`.
   - Уже помеченные части при повторном слиянии заново не помечаются. Помеченной считается заметка, которая начинается с `HH:MM ` (`ReadingProgressCreation::TIME_MARK`). Заметку, которую пользователь сам начал со времени, мутация тоже сочтёт помеченной — это осознанно принятый риск.

### Ввод (интерфейс)

- Кнопка в `reading-actions` карточки. По ней карточка через Turbo Frame заменяется панелью: две последние записи (с заметками), общее число страниц и форма новой записи (дата, «с», «по», заметка, галочка «Начать заново»). Так же сейчас работает редактирование reading-а.
- Маршрут: `/users/:user_secret_id/readings/:reading_id/progresses`.
- «С» по умолчанию — `to_page` последней записи текущего захода (последней по `date`, затем по `updated_at`, чтобы учесть слияния); если записей нет — пусто. «По» по умолчанию пусто.
- Галочка «Начать заново» показывается, только если в текущем заходе уже есть записи.
- После сохранения в фрейм возвращается обычная карточка reading-а; кнопка «Закрыть» делает то же без сохранения.
- Кнопка видна только владельцу (`policy(@user).update?`), только у незаконченных reading-ов (`finish: nil`) и не у сборников. Компоненты сборников не исключаются. В модели этих ограничений нет — это правила интерфейса.
- `total_pages` вводится и редактируется в обычной форме reading-а.
- Редактирования и удаления записей в первой итерации нет.

### Отображение

- Reading с записями (кроме сборников) показывается не карточкой, а Bootstrap accordion. В шапке — всё то же, что на обычной карточке; название — кнопка аккордеона с шевроном. В раскрывающейся части — полосы. По умолчанию свёрнуто, состояние между загрузками не запоминается.
- Полосы — по одной на заход, новые ниже старых. Старый заход остаётся незаполненным и показывается приглушённо. Над полосой — даты захода (и «Заход N», если заходов несколько), под полосой — «прочитано X из Y стр. (Z%)».
- Сегмент записи — от `from_page / total_pages` до `to_page / total_pages`; часть за концом книги обрезается; минимальная ширина — 2px. Подсказка на сегменте — дата, «с … по …», число страниц и заметка.
- Цвет: палитра из 5 цветов, у каждого дня чтения — случайный цвет, отличный от цвета предыдущего дня; записи одного дня — одного цвета. Случайность детерминирована (зерно — reading и дата), цвета не меняются между загрузками.
- Перечитанные страницы: сегменты полупрозрачные и накладываются, перекрытие выглядит темнее; в процентах каждая страница учитывается один раз.
- Без `total_pages`: полосы нет, только «прочитано X стр.»; владельцу — ссылка «Укажите число страниц в книге» на форму редактирования.
- Полосы видны всем, кто открывает страницу книг пользователя.

## Точки опоры в текущем коде

- `Reading` ([app/models/reading.rb](../../app/models/reading.rb)) — факт чтения книги пользователем: `start`, `finish` (`nil` — не дочитана), `professional`, `significant`, `compilation_reading_id`. `belongs_to :user, touch: true`.
- `Book` ([app/models/book.rb](../../app/models/book.rb)) — **общая для всех пользователей**: `title`, `author`, `short`, `compilation`. Персональных данных здесь быть не должно.
- `Users::BooksController` — CRUD reading-ов; `:id` в маршрутах `users/:user_secret_id/books/:id` — это id reading-а. Поэтому прогресс живёт под отдельным маршрутом `readings/:reading_id/progresses`.
- Панель reading-а — [_reading.html.erb](../../app/views/users/books/_reading.html.erb): Bootstrap `card` внутри `turbo_frame_tag(dom_id(reading))`; кнопка «Изменить» заменяет её формой в том же фрейме. Список — `_readings_list.html.erb`, сборники — `_compilation.html.erb`.
- Бизнес-логика создания reading-а — [app/mutations/reading_creation.rb](../../app/mutations/reading_creation.rb); логику записи прогресса стоит оформить так же.
- `ReadingDecorator` — методы для вида (`labels`, `hint`, `finish_date`); сюда естественно ложатся методы для полос прогресса.
- Сворачивание уже есть у сборников: Stimulus `compilation_controller.js` по клику на название. Для полос нужен отдельный триггер, чтобы не конфликтовать.
- Bootstrap 5.3 даёт `.progress` и `.progress-stacked`. Stacked рассчитан на сегменты, идущие подряд; для диапазонов с пропусками и перекрытиями, скорее всего, понадобится своё позиционирование сегментов (`left` и `width` в процентах).
- Список reading-ов собирает `UserReadingHistoryDecorator`; при выводе прогресса понадобится `includes`, чтобы не получить N+1.

## Открытые вопросы

У каждого вопроса — варианты и предварительная рекомендация. Рекомендация — не решение. Вопросы 1–7 и 9 закрыты, 8 — частично.

### 8. Заходы (что осталось; к этапу 4)

- **Отмечать ли галочку «Начать заново» автоматически?** Если «с» меньше последнего «по» текущего захода, форма может сама поставить галочку и показать почему — это исходная идея владельца, а снять галочку можно. Рекомендация: да.

### 10. Цвета соседних на полосе сегментов (к этапу 4)

Сейчас цвет дня отличается только от цвета **предыдущего дня чтения** — подряд идущие дни совпасть не могут, это покрыто тестом. Но соседство на полосе — это соседство по страницам, а не по времени. При чтении вразброс (день 1: 100–120, день 2: 0–20, день 3: 120–140) сегменты дней 1 и 3 стоят рядом и могут получить один цвет; то же с перекрывающимися сегментами.

- **А.** Исключать не только цвет предыдущего дня, но и цвета всех уже раскрашенных дней, чьи сегменты касаются или перекрывают сегменты этого дня. С 5 цветами решение почти всегда есть; если нет — брать любой, кроме цвета предыдущего дня.
- **Б.** Оставить как есть.
- Рекомендация: А.
- Побочный эффект в обоих вариантах: запись задним числом может перекрасить последующие дни захода, потому что цвет зависит от предыдущих.

## Реализация

### Этап 1 (2026-11-01)

- Миграции: `db/migrate/20261101120000_add_progress_fields_to_readings.rb`, `db/migrate/20261101120100_create_reading_progresses.rb`. `reading_progresses.reading_id` — integer, потому что `readings.id` — serial; индекс `[reading_id, attempt, date]`.
- `ReadingProgress` ([app/models/reading_progress.rb](../../app/models/reading_progress.rb)): дата по умолчанию — `Time.zone.today`, пустая заметка нормализуется в `nil`. Проверку `to_page ≤ total_pages` владелец убрал.
- `Reading#progresses` (`has_many`, `dependent: :delete_all`), валидации `total_pages` и `attempt`.
- `ReadingProgressCreation.run(reading, params, start_over: false)` ([app/mutations/reading_progress_creation.rb](../../app/mutations/reading_progress_creation.rb)) возвращает сохранённую запись (при слиянии — уцелевшую) или несохранённую с ошибками. При ошибке валидации счётчик заходов не растёт.
- Specs: `spec/models/reading_progress_spec.rb`, `spec/mutations/reading_progress_creation_spec.rb`, валидации в `spec/models/reading_spec.rb`. В `rails_helper` подключены `ActiveSupport::Testing::TimeHelpers`.
- Фабрики: у `book` появилось название по умолчанию (последовательность), у `reading` — `user` и `book` по умолчанию.

### Этап 2 (2026-11-01)

- Маршрут: `resources :readings, only: [] { resources :progresses, only: [:new, :create] }` внутри `resources :users`. Хелперы — `new_user_reading_progress_path(user, reading)` и `user_reading_progresses_path(user, reading)`.
- `Users::Readings::ProgressesController` ([app/controllers/users/readings/progresses_controller.rb](../../app/controllers/users/readings/progresses_controller.rb)): `new` рисует панель, `create` вызывает `ReadingProgressCreation` и возвращает карточку (`users/books/_reading`) или панель с ошибками и статусом 422. Чужой reading — 404, чужой пользователь — 403.
- Панель — [app/views/users/readings/progresses/new.html.erb](../../app/views/users/readings/progresses/new.html.erb). Поля формы — `reading_progress[...]`, галочка — `start_over`. У id полей префикс `dom_id(reading)`, чтобы несколько открытых панелей не конфликтовали.
- `Reading#last_progress` — последняя запись текущего захода (по `date`, затем по `updated_at`); `ReadingProgress.latest_first` — соответствующий порядок.
- Кнопка-закладка (`a.progress-button`) в `_reading.html.erb`; видимость — `ReadingDecorator#progress_trackable?`. Колонка `.reading-actions` — flex с выравниванием по правому краю, ширина 130px под четыре кнопки.
- `total_pages` добавлено в форму создания reading-а (`_form.html.erb`, поле `Pages`) и в форму редактирования (`edit.html.erb`); разрешено в `BooksController#reading_params`.
- Specs: `spec/requests/reading_progresses_spec.rb`, кнопка и `total_pages` в `spec/requests/books_spec.rb`.

### Этап 3 (2026-11-02)

- `ReadingProgressMap` ([app/decorators/reading_progress_map.rb](../../app/decorators/reading_progress_map.rb)) превращает записи в полосы: `bars` (по одной на заход, `Bar` с `segments`, `pages_read`, `percent`, `summary`, `dates`), цвета дней, объединение диапазонов, обрезка по `total_pages`. `PALETTE_SIZE` должен совпадать с числом классов `.progress-color-N` в `books.scss`.
- `ReadingDecorator#progress_bars?` (есть записи и это не сборник) и `#progress_map`.
- `_reading.html.erb` рисует либо обычную карточку, либо accordion; общая строка (название, дата, кнопки) вынесена в `_reading_row.html.erb`, полосы — в `_reading_progress.html.erb`. Сворачивание — штатный JS Bootstrap (`data-bs-toggle="collapse"`), своего Stimulus-контроллера нет.
- `UserReadingHistoryDecorator` подгружает `progresses` через `includes`.
- Стили — в `books.scss`: аккордеон под вид карточки, `.progress-map`, `.progress-map-segment`, `.progress-color-0..4`.
- Specs: `spec/decorators/reading_progress_map_spec.rb`, полосы в `spec/requests/books_spec.rb`.
